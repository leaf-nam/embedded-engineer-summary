# 1. 임베디드 하드웨어

## 1.1 논리회로

### 1) 논리회로 기초

디지털 시스템은 연속적인 아날로그 신호를 0과 1 두 가지 논리값으로 변환해 처리하는 시스템이다. 임베디드 하드웨어는 센서의 아날로그 값을 ADC로 디지털화하고, 논리회로와 프로세서로 연산한 뒤 다시 DAC나 액추에이터로 출력한다.

**불 대수(Boolean Algebra)**는 0과 1만을 사용하는 논리 연산 체계다. 논리식 간소화의 기본 법칙은 다음과 같다.

| 법칙 | OR 형태 | AND 형태 |
|---|---|---|
| 교환 | \(A+B=B+A\) | \(AB=BA\) |
| 결합 | \((A+B)+C=A+(B+C)\) | \((AB)C=A(BC)\) |
| 분배 | \(A(B+C)=AB+AC\) | \(A+BC=(A+B)(A+C)\) |
| 흡수 | \(A+AB=A\) | \(A(A+B)=A\) |
| 멱등 | \(A+A=A\) | \(AA=A\) |
| 보수 | \(A+\bar{A}=1\) | \(A\bar{A}=0\) |
| 드모르간 | \(\overline{A+B}=\bar{A}\bar{B}\) | \(\overline{AB}=\bar{A}+\bar{B}\) |

논리식은 대수적 간소화 또는 **카르노맵(Karnaugh Map)**으로 간소화한다. 카르노맵은 인접한 1(또는 0)을 2의 거듭제곱 개수로 묶어 최소 항을 만든다. 무관항(Don't Care)은 필요에 따라 1이나 0으로 취급해 묶음을 크게 만들 수 있다.

**수의 표현**은 시험에서 계산 문제로 자주 출제된다.

| 표현 | 특징 | 예: 8비트에서 -5 |
|---|---|---|
| 부호-절대값 | 최상위 비트가 부호, 나머지가 크기 | `1000 0101` |
| 1의 보수 | 양수의 모든 비트 반전 | `1111 1010` |
| 2의 보수 | 1의 보수 + 1 | `1111 1011` |

- \(n\)비트 2의 보수 범위: \(-2^{n-1} \sim 2^{n-1}-1\)
- 2의 보수에서 덧셈·뺄셈을 같은 회로로 처리할 수 있어 ALU 설계가 단순해진다.
- **BCD**는 10진수 한 자리를 4비트로 표현한다. `1001`(9) 다음 `1010`은 BCD에서 사용하지 않는다.
- **그레이 코드**는 인접한 코드가 1비트만 달라지는 코드로, 센서·엔코더에서 오차를 줄인다.
- **패리티 비트**는 1의 개수를 짝수 또는 홀수로 맞춰 1비트 오류를 검출한다. 2비트 오류는 검출하지 못할 수 있다.
- **해밍 코드**는 여러 개의 패리티 비트로 오류 검출과 1비트 정정을 수행한다.

**시험 포인트:** 2의 보수 변환, 부호 확장, 오버플로 판별(같은 부호끼리 더해 결과 부호가 바뀌면 오버플로), BCD 보정(`+6`)을 자주 묻는다.

### 2) 조합논리회로

조합논리회로는 현재 입력만으로 출력이 결정되고 기억 소자가 없는 회로다.

| 게이트 | 논리식 | 설명 |
|---|---|---|
| AND | \(Y=AB\) | 모두 1일 때 1 |
| OR | \(Y=A+B\) | 하나라도 1이면 1 |
| NOT | \(Y=\bar{A}\) | 반전 |
| NAND | \(Y=\overline{AB}\) | AND의 반전, 범용 게이트 |
| NOR | \(Y=\overline{A+B}\) | OR의 반전, 범용 게이트 |
| XOR | \(Y=A\oplus B\) | 서로 다를 때 1 |
| XNOR | \(Y=\overline{A\oplus B}\) | 서로 같을 때 1 |

**반가산기(Half Adder)**는 1비트 두 수를 더해 합(S)과 자리올림(C)을 만든다. **전가산기(Full Adder)**는 아래 자리에서 올라온 자리올림까지 포함한다.

\[
S = A \oplus B \oplus C_{in}, \qquad C_{out} = AB + C_{in}(A \oplus B)
\]

- **디코더(Decoder)**: \(n\)비트 입력으로 \(2^n\)개 출력 중 하나를 선택한다.
- **인코더(Encoder)**: 여러 입력 중 활성화된 입력의 번호를 이진수로 출력한다. 우선순위 인코더는 동시 입력 시 우선순위가 높은 입력을 선택한다.
- **멀티플렉서(MUX)**: 여러 데이터 입력 중 선택 신호에 따라 하나를 출력한다. \(2^n:1\) MUX는 선택선 \(n\)개가 필요하다.
- **디멀티플렉서(DEMUX)**: 하나의 입력을 선택 신호에 따라 여러 출력으로 분배한다.
- **비교기**: 두 수의 대소·일치를 판별한다.
- **패리티 발생기/검사기**: 1의 개수를 맞추거나 오류를 검출한다.

조합논리회로 설계 절차는 ① 진리표 작성 → ② 논리식 유도 → ③ 간소화 → ④ 게이트 회로 구현 순서다. 출력이 1인 행을 묶으면 최소항(SOP), 0인 행을 묶으면 최대항(POS)이 된다.

**타이밍**에서 게이트 지연이 경로마다 다르면 순간적으로 잘못된 출력인 **글리치(Glitch)**가 발생할 수 있다. 이를 논리적 해저드라 하며, 중복 항을 추가하거나 동기식 설계로 해결한다.

### 3) 순서논리회로

순서논리회로는 현재 입력과 이전 상태를 함께 사용해 출력을 결정한다. 기억 소자로 래치와 플립플롭을 사용한다.

| 소자 | 트리거 | 특징 |
|---|---|---|
| SR 래치 | 레벨 | S=1, R=1 입력이 금지 |
| D 래치 | 레벨 | 입력 D를 그대로 저장, 투명 모드 존재 |
| D 플립플롭 | 에지 | 클록 에지에서 D를 저장, 가장 많이 사용 |
| JK 플립플롭 | 에지 | J=K=1이면 토글, SR의 금지 상태 보완 |
| T 플립플롭 | 에지 | T=1이면 토글, 카운터에 사용 |

특성방정식은 다음과 같다.

\[
Q^{+}=D \qquad Q^{+}=J\bar{Q}+\bar{K}Q \qquad Q^{+}=T\oplus Q
\]

- **레지스터**: 여러 플립플롭을 묶어 데이터를 병렬로 저장한다.
- **시프트 레지스터**: 클록마다 비트를 좌·우로 이동한다. 직렬-병렬 변환, 지연 회로에 사용한다.
- **카운터**: 클록 펄스를 세는 회로다. 비동기(리플) 카운터는 앞 단의 출력이 다음 단의 클록이 되어 전파 지연이 누적된다. 동기 카운터는 모든 플립플롭에 같은 클록을 인가해 지연 문제를 줄인다.
- **모듈러스(Modulus)**: \(N\)진 카운터는 \(N\)개의 상태를 가진다. \(n\)비트 카운터의 최대 모듈러스는 \(2^n\)이다.
- **링 카운터**: 1을 순환시키며 상태 수가 플립플롭 수와 같다.
- **존슨 카운터**: 마지막 출력을 반전해 궤환시키며 상태 수가 \(2n\)이다.

**유한상태기계(FSM)**는 상태도와 상태표로 설계한다. 출력이 현재 상태에만 의존하면 **무어(Moore)**, 현재 상태와 입력에 의존하면 **밀리(Mealy)** 모델이다. 밀리 모델은 출력이 빠르지만 입력 글리치에 민감하다.

**시험 포인트:** 플립플롭의 여기표(Excitation Table), 상태 전이표, 카운터의 상태 순서, 동기/비동기 차이를 자주 묻는다. **셋업 타임**은 클록 에지 전에 데이터가 안정되어야 하는 시간, **홀드 타임**은 에지 후에도 유지해야 하는 시간이다. 이를 위반하면 **메타스테이빌리티**가 발생한다.

### 4) 메모리

메모리는 전원이 꺼지면 데이터가 사라지는 **휘발성(RAM)**과 유지되는 **비휘발성(ROM, Flash)**으로 나뉜다.

| 종류 | 저장 방식 | 속도 | 집적도 | 용도 |
|---|---|---|---|---|
| SRAM | 플립플롭 | 빠름 | 낮음 | 캐시, 소용량 |
| DRAM | 커패시터 | 보통 | 높음 | 주기억장치 |
| ROM | 마스크 고정 | 읽기 전용 | 높음 | 부트 코드 |
| EPROM | UV 소거 | 읽기 전용 | 높음 | 개발용 |
| EEPROM | 전기 소거 | 느림 | 높음 | 설정값 |
| Flash | 블록 단위 소거 | 보통 | 높음 | 펌웨어, 저장장치 |

- **DRAM**은 커패시터 전하가 누설되므로 주기적인 **리프레시**가 필요하다.
- **SDRAM/DDR**은 클록에 동기화되고 에지마다 데이터를 전송한다. DDR은 상승·하강 에지를 모두 사용한다.
- **NAND Flash**는 집적도가 높고 블록 단위 접근에 유리해 대용량 저장에 쓴다. **NOR Flash**는 랜덤 액세스가 가능해 코드 실행(XIP)에 유리하다.
- Flash는 쓰기 전에 지워야 하며, 지우기 횟수에 수명 제한이 있어 **웨어 레벨링**을 사용한다.

**메모리 용량 계산**은 주소선과 데이터선으로 구한다.

\[
\text{용량} = 2^{\text{주소선 수}} \times \text{데이터선 수 (bit)}
\]

예를 들어 주소선 12개, 데이터선 8개인 메모리는 \(2^{12} \times 8 = 4096 \times 8\)bit = 4KB다. 주소선이 10개면 \(2^{10}=1024\)개 번지에 접근할 수 있다.

**주소 디코딩**은 상위 주소 비트로 칩을 선택(Chip Select)하고 하위 비트로 칩 내부 번지를 지정한다. 여러 칩을 연결할 때 칩 셀렉트 신호를 중복 없이 활성화해야 한다.

### 5) HDL

**HDL(Hardware Description Language)**은 하드웨어의 구조와 동작을 기술하는 언어다. 대표적으로 Verilog와 VHDL이 있다.

- **FPGA**: 현장에서 프로그래밍 가능한 게이트 배열. 소량 생산, 프로토타이핑, 재구성에 유리하다.
- **CPLD**: FPGA보다 규모가 작고 조합논리 구현에 적합하다.
- **ASIC**: 특정 목적에 맞춰 제작한 칩. 대량 생산 시 단가가 낮고 성능이 높지만 개발 비용이 크다.

Verilog의 기본 구조는 다음과 같다.

```verilog
module full_adder(
    input  a, b, cin,
    output sum, cout
);
    assign sum  = a ^ b ^ cin;
    assign cout = (a & b) | (cin & (a ^ b));
endmodule
```

- `assign`은 조합논리, `always`는 순차논리 또는 조합논리를 기술한다.
- 순차논리에서는 **비블로킹 할당(`<=`)**, 조합논리에서는 **블로킹 할당(`=`)**을 사용하는 것이 일반적이다.
- `always @(posedge clk)`는 상승 에지에서 동작하는 플립플롭을 만든다.
- **테스트벤치**는 입력 자극을 만들어 시뮬레이션으로 동작을 검증하는 모듈이다.
- **합성(Synthesis)**은 HDL을 게이트 수준 넷리스트로 변환하는 과정이고, 시뮬레이션은 기능을 검증하는 과정이다.

VHDL은 `entity`(입출력 선언)와 `architecture`(내부 동작)로 구성된다. C언어와 달리 병렬로 동작하는 하드웨어를 기술하므로, 문장 순서보다 신호와 프로세스의 동작 시점이 중요하다.

## 1.2 컴퓨터 구조와 마이크로프로세서

### 1) CPU 구조

CPU는 **ALU**(연산), **제어장치**(명령 해석·제어), **레지스터**(임시 저장)로 구성된다. 이들은 내부 버스로 연결된다.

- **PC(Program Counter)**: 다음에 실행할 명령어 주소
- **IR(Instruction Register)**: 현재 실행 중인 명령어
- **MAR/MBR**: 메모리 주소·데이터 버퍼
- **SP(Stack Pointer)**: 스택 최상단 주소
- **FLAGS/PSW**: 상태 플래그(Zero, Carry, Negative, Overflow)

**폰 노이만 구조**는 명령어와 데이터가 같은 메모리·버스를 공유한다. **하버드 구조**는 명령어 메모리와 데이터 메모리를 분리해 동시 접근이 가능하다. 많은 임베디드 MCU는 수정 하버드 구조를 사용한다.

**명령어 사이클**은 인출(Fetch) → 해독(Decode) → 실행(Execute) → 저장(Write-back) 순서다.

**주소지정방식(Addressing Mode)**은 다음과 같다.

| 방식 | 의미 | 예 |
|---|---|---|
| 즉시 | 명령어에 값이 포함 | `MOV R0, #10` |
| 직접 | 명령어에 주소가 포함 | `LDR R0, [0x1000]` |
| 간접 | 주소를 담은 곳을 참조 | `LDR R0, [R1]` |
| 인덱스 | 기준 주소 + 오프셋 | `LDR R0, [R1, #4]` |
| 상대 | PC 기준 오프셋 | 분기 명령 |
| 스택 | SP 기준 push/pop | `PUSH {R0}` |

**CISC**는 명령어 수가 많고 복잡하며 가변 길이다. **RISC**는 명령어가 단순하고 고정 길이이며, 많은 레지스터와 파이프라인에 유리하다. ARM은 대표적인 RISC 계열이다.

**파이프라인**은 명령어 처리 단계를 겹쳐 처리해 처리량을 높인다. 파이프라인 해저드는 다음과 같다.

| 해저드 | 원인 | 해결 |
|---|---|---|
| 구조적 | 자원 충돌 | 자원 분리, 지연 |
| 데이터 | 앞 명령 결과 필요 | 포워딩, 스톨 |
| 제어 | 분기 결과 미확정 | 지연 슬롯, 분기 예측 |

**슈퍼스칼라**는 여러 명령어를 동시에 발행하고, **분기 예측**은 분기 결과를 미리 추정해 파이프라인을 채운다.

**ARM**은 32/64비트 RISC 프로세서로, 적은 전력으로 높은 성능을 내 임베디드·모바일에 널리 쓰인다. 범용 레지스터, CPSR(상태), 조건부 실행, 다양한 모드(User, IRQ, FIQ, Supervisor 등)를 가진다.

### 2) 메모리 시스템

메모리 계층은 속도·용량·비용의 균형을 맞춘다.

| 계층 | 속도 | 용량 | 비용 |
|---|---|---|---|
| 레지스터 | 가장 빠름 | 가장 작음 | 가장 비쌈 |
| 캐시 | 빠름 | 작음 | 비쌈 |
| 주기억장치 | 보통 | 큼 | 보통 |
| 보조기억장치 | 느림 | 가장 큼 | 저렴 |

**지역성(Locality)**은 시간 지역성(최근 사용한 데이터를 다시 사용)과 공간 지역성(인접 데이터를 사용)으로 나뉜다. 캐시는 이 원리로 적중률을 높인다.

**캐시 매핑** 방식은 다음과 같다.

| 방식 | 특징 | 장단점 |
|---|---|---|
| 직접 매핑 | 주소로 위치 고정 | 구현 단순, 충돌 잦음 |
| 완전 연관 | 어느 위치나 가능 | 적중률 높음, 비교기 많음 |
| 집합 연관 | 여러 웨이로 구성 | 절충형, 일반적 |

주소는 `태그(Tag) | 인덱스(Index) | 오프셋(Offset)`으로 분할된다. 캐시 라인 수가 \(2^n\)이면 직접 매핑에서 인덱스는 \(n\)비트다.

**교체 정책**은 LRU, FIFO, LFU, Random 등이 있다. **쓰기 정책**은 즉시 메모리에 쓰는 Write-through와 나중에 쓰는 Write-back으로 나뉜다.

\[
AMAT = T_{hit} + m \times T_{miss}
\]

여기서 \(m\)은 실패율, \(T_{miss}\)는 실패 시 추가 시간이다.

**MMU**는 가상주소를 물리주소로 변환한다. **페이징**은 주소 공간을 고정 크기 페이지로 나누고 페이지 테이블로 매핑한다. **TLB**는 최근 주소 변환 결과를 저장하는 캐시다. 페이지가 메모리에 없으면 **페이지 폴트**가 발생해 디스크에서 불러온다.

가상주소는 `페이지 번호 | 페이지 오프셋`으로 나뉘고, 페이지 테이블에서 페이지 번호에 대응하는 프레임 번호를 찾아 물리주소를 만든다.

### 3) I/O 인터페이스

CPU가 주변장치와 데이터를 주고받는 방식은 크게 세 가지다.

| 방식 | 동작 | 장단점 |
|---|---|---|
| 폴링 | CPU가 상태를 반복 확인 | 구현 단순, CPU 낭비 |
| 인터럽트 | 장치가 CPU에 알림 | 효율적, 지연·우선순위 관리 필요 |
| DMA | 전용 컨트롤러가 전송 | 대량 전송에 효율적, 버스 공유 필요 |

**메모리 맵 I/O**는 장치 레지스터를 메모리 주소 공간에 배치해 일반 load/store 명령으로 접근한다. **고립형 I/O**는 별도의 I/O 포트 공간과 명령(`IN`, `OUT`)을 사용한다.

**인터럽트 처리 과정**은 ① 장치가 IRQ 신호 발생 → ② CPU가 현재 작업 저장 → ③ 인터럽트 벡터로 ISR 주소 확인 → ④ ISR 실행 → ⑤ 복귀 순서다. 중첩 인터럽트를 허용하려면 우선순위와 마스킹을 관리한다.

**DMA**는 CPU를 거치지 않고 메모리와 장치 사이를 전송한다. 전송 완료 시 인터럽트를 발생시킨다. 버스 마스터 방식과 사이클 스틸링 방식이 있다.

**버퍼링**은 속도 차이를 흡수하고, **핸드셰이킹**은 송수신 준비 상태를 주고받아 동기를 맞춘다.

### 4) 임베디드 시스템 구조

임베디드 시스템은 특정 기능을 수행하도록 하드웨어와 소프트웨어를 결합한 전용 컴퓨터 시스템이다.

- **실시간성**: 정해진 시간 안에 결과를 내야 한다.
- **자원 제약**: CPU, 메모리, 전력, 비용이 제한된다.
- **신뢰성**: 장기간 무인 동작과 오류 복구가 필요하다.
- **전용성**: 범용 PC와 달리 목적이 고정되어 있다.

| 구분 | 특징 |
|---|---|
| MCU | CPU·메모리·주변장치를 한 칩에 통합 |
| MPU | 프로세서 코어 중심, 외부 메모리 사용 |
| SoC | 여러 기능 블록을 하나의 칩에 통합 |
| DSP | 디지털 신호 처리에 특화 |
| FPGA | 하드웨어 재구성 가능 |

**하드웨어/소프트웨어 분할**은 성능, 전력, 비용, 개발 기간을 고려해 기능을 하드웨어와 소프트웨어에 배분하는 과정이다.

개발 흐름은 요구사항 분석 → 하드웨어 선정 → 보드 설계 → 부트로더·커널 포팅 → 디바이스 드라이버 → 응용 프로그램 → 통합 테스트 순서다.

## 1.3 주변장치

### 1) 입출력 포트

**GPIO(General Purpose Input/Output)**는 소프트웨어로 방향과 값을 제어할 수 있는 범용 핀이다. 일반적으로 다음 레지스터를 가진다.

- **방향 레지스터(DDR)**: 입력/출력 설정
- **데이터 레지스터(PORT/ODR)**: 출력 값 또는 입력 값
- **상태 레지스터(PIN/IDR)**: 실제 핀 상태
- **풀업/풀다운 설정**: 미연결 시 전위 고정

GPIO를 제어할 때는 다른 비트를 건드리지 않도록 **비트 마스크**를 사용한다.

```c
#define LED_PIN   (1u << 5)

GPIOA->MODER &= ~(3u << (5 * 2));  // PA5 기능 비트 초기화
GPIOA->MODER |=  (1u << (5 * 2));  // PA5를 출력 모드로
GPIOA->ODR   |=  LED_PIN;          // LED 켜기
GPIOA->ODR   &= ~LED_PIN;          // LED 끄기
```

**포트 멀티플렉싱**은 하나의 핀이 GPIO, UART, SPI 등 여러 기능 중 하나를 선택하도록 설정하는 것이다. 데이터시트의 핀 설명과 대체 기능 표를 확인해야 한다.

**데이터시트**에서는 ① 핀 배열과 기능, ② 레지스터 맵과 비트 필드, ③ 전기적 특성(전압·전류), ④ 타이밍 다이어그램을 확인한다.

기계식 버튼은 접점 떨림이 발생하므로 **디바운싱**(소프트웨어 지연 또는 RC 회로)이 필요하다. 오픈 드레인 출력은 여러 장치가 하나의 선을 공유하는 I2C 등에 사용한다.

### 2) 주요 주변장치

**직렬 통신**은 대표적으로 UART, I2C, SPI가 있다.

| 구분 | UART | I2C | SPI |
|---|---|---|---|
| 배선 | TX, RX | SDA, SCL | MOSI, MISO, SCK, CS |
| 방식 | 비동기 | 동기 | 동기 |
| 속도 | 보통 | 느림 | 빠름 |
| 다중 장치 | 1:1 | 주소로 다중 | CS로 다중 |
| 특징 | 시작/정지 비트, 보율 | 2선, ACK | 4선, 전이중 |

- **UART**는 클록선 없이 약속된 보율(Baud Rate)로 통신한다. 시작 비트, 데이터 비트, 패리티, 정지 비트로 프레임을 구성한다.
- **I2C**는 SDA/SCL 두 선으로 통신하며, 주소로 슬레이브를 선택하고 ACK로 수신을 확인한다. 풀업 저항이 필요하다.
- **SPI**는 마스터가 CS로 슬레이브를 선택하고 SCK로 동기를 맞춘다. 전이중 통신이 가능하고 속도가 빠르지만 선 수가 많다.

**타이머/카운터**는 클록을 세어 시간 지연, 주기 측정, PWM 생성에 사용한다. **PWM**은 득점 주기 대비 HIGH 비율인 득점률(Duty Cycle)로 모터 속도나 LED 밝기를 제어한다.

**ADC**는 아날로그 전압을 디지털 값으로 변환한다. 분해능(8/10/12비트), 기준 전압, 샘플링 속도, 양자화 오차가 중요하다. **DAC**는 반대로 디지털 값을 아날로그 전압으로 변환한다.

\[
\text{ADC 값} = \frac{V_{in}}{V_{ref}} \times (2^n - 1)
\]

**센서**는 초음파(거리), 적외선(근접), 온도(서미스터, LM35), 가속도·자이로·지자기(모션) 등이 있다. 센서 출력이 아날로그면 ADC, 디지털이면 I2C/SPI를 사용한다.

**USB**는 호스트 중심의 직렬 버스로, 열거(Enumeration) 과정에서 장치 정보를 교환한다. **이더넷/Wi-Fi**는 네트워크 인터페이스로, MAC/PHY 계층과 TCP/IP 스택을 통해 통신한다.

**칩 셀렉트(CS)**는 여러 주변장치 중 하나를 선택하는 신호다. **전원 제어 인터페이스**는 레귤레이터, PMIC, 슬립 모드를 통해 전력 소모를 줄인다.

# 2. 임베디드 펌웨어

## 2.1 펌웨어

### 1) 펌웨어와 JTAG

**펌웨어**는 하드웨어를 제어하기 위해 비휘발성 메모리에 저장된 소프트웨어다. 부트로더, 디바이스 초기화 코드, RTOS, 응용 코드가 포함될 수 있다.

**스타트업 코드(Startup Code)**는 리셋 직후 실행되어 다음을 수행한다.

1. 스택 포인터 설정
2. 인터럽트 벡터 테이블 배치
3. `.data` 영역을 Flash에서 RAM으로 복사
4. `.bss` 영역을 0으로 초기화
5. 클록·메모리 컨트롤러 초기화
6. `main()` 호출

`.bss`는 초기값이 0인 전역·정적 변수 영역으로, 실행 파일에 실제 데이터를 저장하지 않고 크기 정보만 가진다. 따라서 `.bss`가 크면 RAM 사용량은 늘지만 바이너리 크기는 늘지 않는다.

**JTAG**는 IEEE 1149.1 표준으로, TCK, TMS, TDI, TDO, TRST 핀을 사용한다. 경계 스캔(Boundary Scan)으로 보드 연결을 검사하고, CPU를 디버그 모드로 제어해 레지스터·메모리를 읽고 중단점을 설정한다. **SWD**는 ARM에서 JTAG을 2선으로 줄인 디버그 인터페이스다.

**ISP/ICP**는 부트로더나 전용 회로를 통해 Flash에 펌웨어를 기록하는 방식이다. 양산에서는 JTAG보다 ISP를 많이 사용한다.

**ELF**는 실행 파일·오브젝트 파일의 표준 형식이다. 주요 섹션은 `.text`(코드), `.data`(초기값 있는 데이터), `.bss`(초기값 0), `.rodata`(상수), `.symtab`(심볼)이다. `readelf`, `objdump`, `objcopy`, `nm`, `size`, `strip` 같은 binutils 도구로 분석한다.

- `objcopy -O binary`로 ELF를 순수 바이너리로 변환한다.
- `objdump -d`로 역어셈블해 기계어를 분석한다.
- `size`로 text/data/bss 크기를 확인한다.

### 2) 부트로더

**부트로더**는 전원 인가 후 가장 먼저 실행되어 하드웨어를 초기화하고 OS 커널을 메모리에 적재해 실행하는 프로그램이다.

일반적인 부팅 순서는 다음과 같다.

1. Boot ROM 실행
2. 1차 부트로더(SPL)가 DRAM 초기화
3. 2차 부트로더(U-Boot proper) 실행
4. 커널 이미지와 Device Tree를 메모리에 로드
5. 커널에 제어권 이전

**U-Boot**는 대표적인 오픈소스 부트로더다. `printenv`, `setenv`, `saveenv`, `mmc`, `tftp`, `nfs`, `bootm`, `bootz` 등의 명령을 제공한다. 환경 변수는 Flash나 eMMC에 저장할 수 있다.

**부트로더의 역할**은 다음과 같다.

- 클록, UART, DRAM, Flash 초기화
- 커널·initramfs·DTB 로드
- 커널 부팅 인자 전달
- 네트워크 부팅(TFTP/NFS) 지원
- 복구 모드, 펌웨어 업데이트, 보안 검증

**initramfs**는 커널 부팅 초기에 필요한 최소 파일 시스템을 메모리에 올려 사용하는 이미지다. 실제 루트 파일 시스템을 마운트하기 전에 드라이버 모듈을 로드하거나 복구 환경을 제공한다.

**플래시 관리**는 지우기 블록, 배드 블록, 웨어 레벨링, ECC를 고려해야 한다. NAND는 배드 블록 관리가 필수적이다.

### 3) 전원관리

임베디드 시스템은 배터리 수명과 발열 때문에 전원관리가 중요하다.

- **클록 게이팅(Clock Gating)**: 사용하지 않는 블록의 클록을 차단
- **파워 게이팅(Power Gating)**: 사용하지 않는 블록의 전원을 차단
- **DVFS**: 부하에 따라 전압과 주파수를 동적으로 조절
- **슬립 모드**: CPU·주변장치를 저전력 상태로 전환
- **틱리스(Tickless)**: 유휴 시 주기적 타이머 인터럽트를 줄여 소비 전력 절감

**Wake-up Source**는 슬립 상태에서 시스템을 깨우는 신호다. GPIO 인터럽트, RTC 알람, UART 수신, 버튼 등이 있다.

**리눅스 전원관리**는 런타임 PM(개별 장치), 시스템 suspend(STR), hibernation 등을 제공한다. 서스펜드 진입 시 장치 드라이버의 suspend 콜백이 호출되고, 복귀 시 resume 콜백이 호출된다. 드라이버는 레지스터 상태를 저장·복원해야 한다.

## 2.2 OS 포팅

### 1) 교차개발 환경

**교차개발(Cross Development)**은 호스트 PC에서 타깃 보드용 실행 파일을 빌드하는 방식이다.

- **호스트**: 개발 PC (x86)
- **타깃**: 임베디드 보드 (ARM 등)
- **크로스 컴파일러**: 호스트에서 타깃 코드를 생성하는 컴파일러
- **툴체인**: 컴파일러, 어셈블러, 링커, 라이브러리, 디버거의 묶음
- **sysroot**: 타깃용 헤더와 라이브러리 루트 디렉터리

예: `arm-linux-gnueabihf-gcc`는 ARM 하드웨어 부동소수점 ABI용 크로스 컴파일러다.

**원격 디버깅**은 타깃에서 `gdbserver`를 실행하고 호스트의 `gdb`가 네트워크로 연결하는 방식이다. JTAG 디버거를 사용하면 부트로더 초기 단계부터 디버깅할 수 있다.

**빌드 자동화**는 Makefile, CMake, Buildroot, Yocto 등을 사용한다. Buildroot는 비교적 단순한 이미지 구성에, Yocto는 레이어 기반의 대규모 커스터마이징에 적합하다.

### 2) 리눅스 커널 구조와 빌드

리눅스 커널은 모놀리식 구조이면서 로드 가능한 모듈을 지원한다.

| 디렉터리 | 역할 |
|---|---|
| `arch/` | 아키텍처별 코드 |
| `kernel/` | 스케줄러, 시그널, 시간 관리 |
| `mm/` | 메모리 관리 |
| `fs/` | 파일 시스템 |
| `drivers/` | 디바이스 드라이버 |
| `net/` | 네트워크 스택 |
| `include/` | 공용 헤더 |
| `init/` | 커널 초기화 |

커널 설정은 `Kconfig`에 정의되고, `make menuconfig`로 `.config`를 만든다. `defconfig`는 보드별 기본 설정이다.

- **vmlinux**: 디버그 심볼이 포함된 ELF 커널
- **Image**: 압축하지 않은 커널 이미지
- **zImage**: 압축된 커널 이미지
- **uImage**: U-Boot용 헤더가 붙은 이미지
- **DTB**: Device Tree Blob, 하드웨어 구성을 기술한 바이너리

Device Tree는 커널 소스 수정 없이 보드의 주소·인터럽트·핀 구성을 전달한다. `.dts`를 컴파일해 `.dtb`를 만든다.

**커널 모듈**은 `insmod`, `rmmod`, `modprobe`, `lsmod`, `modinfo`로 관리한다. 모듈은 커널과 같은 컴파일러·설정으로 빌드해야 하며, 심볼 버전이 맞지 않으면 로드되지 않는다.

### 3) 리눅스 부팅 과정

리눅스 부팅은 다음과 같은 단계로 진행된다.

1. **Boot ROM**: 최소한의 코드로 부트로더를 로드
2. **부트로더**: DRAM 초기화, 커널·DTB 로드
3. **커널**: 압축 해제, 아키텍처 초기화, 메모리·스케줄러 초기화
4. **드라이버 초기화**: Device Tree를 기반으로 장치 probe
5. **루트 파일 시스템 마운트**
6. **init 프로세스 실행**: `systemd` 또는 `SysV init`
7. **사용자 공간 서비스 시작**

**init 스크립트**는 `/etc/inittab`, `/etc/init.d/`, `systemd` 유닛 등으로 서비스를 시작한다. **BusyBox**는 작은 크기로 init, 셸, 기본 유틸리티를 제공해 임베디드 루트 파일 시스템에 많이 사용한다.

**공유 라이브러리**는 `/lib`, `/usr/lib`에 위치하며 `ld.so`가 런타임에 로드한다. `ldd`로 의존성을 확인하고, `LD_LIBRARY_PATH`로 경로를 지정할 수 있다.

**부팅 실패 디버깅**은 UART 콘솔 로그, `dmesg`, 루트 파일 시스템 마운트 오류, 커널 command line(`console=`, `root=`, `init=`)을 확인한다.

## 2.3 디바이스 드라이버 개발

### 1) 디바이스 드라이버 개념

**디바이스 드라이버**는 하드웨어를 추상화해 커널과 응용 프로그램이 일관된 인터페이스로 장치를 사용하도록 하는 커널 모듈이다.

| 종류 | 접근 단위 | 예 |
|---|---|---|
| 문자(Character) | 바이트 스트림 | UART, GPIO, 센서 |
| 블록(Block) | 고정 크기 블록 | eMMC, SD, SSD |
| 네트워크(Network) | 패킷 | Ethernet, Wi-Fi |

리눅스는 **주 번호(Major)**로 드라이버를, **부 번호(Minor)**로 개별 장치를 식별한다. 장치 파일은 `/dev`에 있고, `udev`가 커널 이벤트에 따라 자동 생성한다.

**플랫폼 디바이스/드라이버** 모델은 버스로 자동 검색되지 않는 SoC 내장 장치를 Device Tree로 등록하고, 드라이버의 `probe()`에서 초기화한다.

**커널 모듈 생명주기**는 `module_init()` → `probe()` → 동작 → `remove()` → `module_exit()` 순서다.

### 2) 문자 디바이스 드라이버

문자 디바이스 드라이버는 `file_operations` 구조체에 콜백을 등록한다.

```c
static const struct file_operations my_fops = {
    .owner   = THIS_MODULE,
    .open    = my_open,
    .release = my_release,
    .read    = my_read,
    .write   = my_write,
    .unlocked_ioctl = my_ioctl,
};
```

- `open()`: 장치 사용 준비, 참조 카운트 증가
- `release()`: 자원 해제, 참조 카운트 감소
- `read()`: 커널 → 사용자 공간으로 데이터 복사
- `write()`: 사용자 → 커널 공간으로 데이터 복사
- `ioctl()`: 장치별 제어 명령

사용자 공간과 커널 공간은 직접 메모리를 공유하지 않으므로 `copy_to_user()`, `copy_from_user()`를 사용한다. 이 함수들은 실패 시 복사하지 못한 바이트 수를 반환하므로 반드시 확인한다.

드라이버 등록은 `register_chrdev()` 또는 `alloc_chrdev_region()` + `cdev_add()`를 사용한다. `/sys/class`에 클래스를 만들고 `device_create()`로 장치 노드를 자동 생성할 수 있다.

```c
static int __init my_init(void)
{
    alloc_chrdev_region(&devno, 0, 1, "mydev");
    cdev_init(&my_cdev, &my_fops);
    cdev_add(&my_cdev, devno, 1);
    my_class = class_create("myclass");
    device_create(my_class, NULL, devno, NULL, "mydev");
    return 0;
}
```

**ioremap()**은 물리 주소의 장치 레지스터를 커널 가상 주소로 매핑한다. 이후 `readl()`, `writel()`로 접근한다. `request_mem_region()`으로 주소 영역을 예약해 충돌을 방지한다.

### 3) 커널 서비스와 동기화

**커널 메모리 할당**은 `kmalloc()`(연속된 물리 메모리, 크기 제한)과 `vmalloc()`(가상적으로 연속, 큰 메모리)을 사용한다. `kfree()`로 해제하며, `GFP_KERNEL`은 슬립 가능한 컨텍스트, `GFP_ATOMIC`은 인터럽트 컨텍스트에서 사용한다.

**동기화 기법**은 다음과 같다.

| 기법 | 슬립 | 사용 문맥 |
|---|---|---|
| 스핀락 | 불가 | 인터럽트, 짧은 임계구역 |
| 뮤텍스 | 가능 | 프로세스 문맥 |
| 세마포 | 가능 | 프로세스 문맥 |
| 원자적 연산 | 불가 | 카운터 |
| RCU | 불가 | 읽기 많은 자료구조 |

**인터럽트 처리**는 빠른 처리를 하는 상반부(Top Half)와 지연 가능한 하반부(Bottom Half)로 나뉜다. 하반부는 tasklet, workqueue, threaded IRQ로 구현한다. workqueue는 프로세스 문맥에서 실행되어 슬립이 가능하다.

**대기 큐(Wait Queue)**는 조건이 만족될 때까지 프로세스를 재우고, `wake_up()`으로 깨운다. **커널 타이머**는 `jiffies` 기반으로 지연 작업을 예약한다.

**DMA API**는 `dma_alloc_coherent()`로 일관된 매핑을 제공하고, 스트리밍 매핑은 `dma_map_single()`을 사용한다. 캐시 일관성을 위해 `dma_sync_single_for_cpu/device()`를 호출한다.

# 3. 임베디드 플랫폼

## 3.1 운영체제

### 1) OS 기본 개념

**운영체제**는 하드웨어 자원을 관리하고 응용 프로그램에 실행 환경을 제공하는 시스템 소프트웨어다.

- **자원 관리자**: CPU, 메모리, 장치, 파일 관리
- **가상 머신**: 응용 프로그램에 추상화된 실행 환경 제공
- **시스템 콜**: 응용 프로그램이 커널 기능을 요청하는 인터페이스

**모놀리식 커널**은 모든 기능이 하나의 커널 공간에서 동작해 성능이 좋지만 결함 영향이 크다. **마이크로커널**은 최소 기능만 커널에 두고 서버 프로세스로 분리해 안정성이 높지만 통신 비용이 든다. **하이브리드**는 두 방식을 절충한다.

**GPOS**는 공정한 자원 분배와 처리량을 중시하고, **RTOS**는 정해진 시간 제약의 준수를 중시한다.

| 구분 | 의미 | 예 |
|---|---|---|
| Hard Real-Time | 마감시간 위반이 치명적 | 항공기 제어, 에어백 |
| Soft Real-Time | 지연이 품질 저하로 이어짐 | 멀티미디어 스트리밍 |
| Firm Real-Time | 결과 가치가 시간이 지나면 0 | 일부 계측 시스템 |

**RTOS**는 우선순위 기반 선점 스케줄링, 짧은 인터럽트 지연, 결정론적 동작을 제공한다. 대표적으로 FreeRTOS, VxWorks, QNX, Zephyr가 있다.

### 2) 프로세스 관리

**프로그램**은 디스크에 저장된 정적인 코드이고, **프로세스**는 실행 중인 프로그램 인스턴스다. **스레드**는 프로세스 내부의 실행 단위로 코드·데이터·힙을 공유하고 스택·레지스터는 개별로 가진다.

**PCB(Process Control Block)**는 PID, 상태, PC, 레지스터, 메모리 정보, 열린 파일, 우선순위 등을 저장한다.

프로세스 상태는 일반적으로 New → Ready → Running → Waiting → Terminated로 전이한다.

- **Ready**: CPU 할당을 기다림
- **Running**: CPU를 사용 중
- **Waiting/Blocked**: I/O 또는 이벤트를 기다림
- **Context Switch**: 문맥을 저장·복원하는 과정으로 오버헤드가 발생

**fork()**는 부모 프로세스를 복사해 자식 프로세스를 만들고, **exec()**는 현재 프로세스 이미지를 새 프로그램으로 교체한다. **wait()**는 자식 종료를 수집해 좀비를 방지한다.

**스레드**는 생성·전환 비용이 적고 자원을 공유해 통신이 쉽지만, 하나의 스레드 오류가 전체 프로세스에 영향을 준다. 공유 자원에는 반드시 동기화가 필요하다.

### 3) CPU 스케줄링

스케줄링은 Ready 큐의 프로세스 중 CPU를 할당할 대상을 결정한다. **선점**은 실행 중인 프로세스를 중단할 수 있고, **비선점**은 스스로 종료될 때까지 기다린다.

| 알고리즘 | 방식 | 특징 |
|---|---|---|
| FCFS | 비선점 | 도착 순서, 호위 효과 |
| SJF | 비선점 | 평균 대기 최소, 실행시간 예측 필요 |
| SRTF | 선점 | 남은 시간 최소 우선 |
| Priority | 선점/비선점 | 우선순위, 기아 발생 |
| Round Robin | 선점 | 시간 할당량, 응답성 좋음 |
| HRRN | 비선점 | 응답비 = (대기+서비스)/서비스 |
| MLQ | 선점 | 고정 우선순위 큐 |
| MLFQ | 선점 | 동적 우선순위, 시간 할당량 조정 |

**평균 대기시간**은 각 프로세스의 (시작 시각 - 도착 시각)의 평균이다. **반환시간**은 (종료 시각 - 도착 시각)이다.

**실시간 스케줄링**에서 **RM(Rate Monotonic)**은 주기가 짧은 작업에 높은 고정 우선순위를 주고, **EDF(Earliest Deadline First)**는 마감시간이 가장 빠른 작업을 동적으로 선택한다. EDF는 CPU 이용률 100%까지 이론적으로 보장한다.

**우선순위 역전**은 낮은 우선순위 작업이 자원을 점유해 높은 우선순위 작업이 대기하는 현상이다. **우선순위 상속** 또는 **우선순위 천장**으로 해결한다.

### 4) 병행성 제어

**임계구역(Critical Section)**은 공유 자원에 접근하는 코드 영역이다. 상호배제, 진행, 한정 대기의 조건을 만족해야 한다.

- **상호배제**: 동시에 하나의 프로세스만 진입
- **진행**: 임계구역이 비어 있으면 진입 가능
- **한정 대기**: 무한정 기다리지 않음

**세마포**는 정수 카운터로 `P(wait)`와 `V(signal)` 연산을 사용한다. 이진 세마포는 뮤텍스처럼, 계수 세마포는 자원 개수 제한에 사용한다. **모니터**는 공유 자원과 연산을 언어 차원에서 캡슐화해 상호배제를 자동 보장한다.

**생산자-소비자** 문제는 버퍼의 빈 공간과 채워진 공간을 세마포로 관리한다. **판독자-기록자** 문제는 읽기 병행성과 쓰기 배타성을 조정한다. **식사하는 철학자** 문제는 교착상태와 기아를 설명하는 대표 예제다.

**교착상태(Deadlock)**의 4가지 필요조건은 다음과 같다.

1. 상호배제
2. 점유와 대기
3. 비선점
4. 환형 대기

대처 방법은 **예방**(조건 제거), **회피**(은행원 알고리즘, 안전 상태 유지), **검출**(자원 할당 그래프), **회복**(프로세스 종료, 자원 선점)이 있다.

### 5) 메모리 관리

**연속 할당**은 프로세스를 연속된 메모리에 배치한다. 외부 단편화가 발생하며 First Fit, Best Fit, Worst Fit으로 배치한다.

**페이징**은 메모리를 고정 크기 페이지로 나눠 외부 단편화를 없앤다. **세그멘테이션**은 논리 단위로 나누어 보호와 공유에 유리하지만 외부 단편화가 생긴다. **페이지드 세그멘테이션**은 두 방식을 결합한다.

**가상 메모리**는 물리 메모리보다 큰 주소 공간을 제공한다. 페이지 테이블로 매핑하고, 접근 시 페이지가 없으면 페이지 폴트가 발생한다.

**페이지 교체 알고리즘**은 다음과 같다.

| 알고리즘 | 특징 |
|---|---|
| OPT | 미래를 알아야 하므로 이론적 최적 |
| FIFO | 먼저 들어온 페이지 교체, Belady 이상 현상 |
| LRU | 가장 오래 사용하지 않은 페이지 교체 |
| LFU | 사용 빈도가 가장 낮은 페이지 교체 |
| Clock | LRU 근사, 참조 비트 사용 |

**Belady의 이상 현상**은 프레임 수를 늘렸는데 페이지 폴트가 오히려 증가하는 현상으로 FIFO에서 발생한다.

**스래싱**은 페이지 폴트가 과도해 실제 작업보다 교체에 시간을 쓰는 상태다. **워킹셋**은 일정 시간 동안 참조한 페이지 집합으로, 프로세스에 필요한 프레임을 보장해 스래싱을 줄인다.

### 6) 장치 및 파일 시스템

I/O 소프트웨어는 사용자 수준 라이브러리 → 시스템 콜 → 장치 독립 계층 → 디바이스 드라이버 → 인터럽트 핸들러 → 하드웨어 순으로 계층화된다.

**디스크 스케줄링**은 탐색 시간을 줄이는 것이 목적이다.

| 알고리즘 | 특징 |
|---|---|
| FCFS | 요청 순서, 공평하지만 비효율 |
| SSTF | 가장 가까운 요청 우선, 기아 가능 |
| SCAN | 한 방향으로 이동 후 반전 (엘리베이터) |
| C-SCAN | 한 방향만 서비스하고 끝에서 복귀 |
| LOOK | 요청이 없으면 반전 |
| C-LOOK | C-SCAN의 LOOK 방식 |

**파일 시스템**은 파일과 디렉터리를 관리한다. **inode**는 파일의 메타데이터(크기, 권한, 블록 위치)를 저장하고, 디렉터리는 이름과 inode 번호를 매핑한다.

**저널링**은 변경 내용을 로그에 먼저 기록해 전원 장애 시 일관성을 복구한다. **RAID**는 여러 디스크를 묶어 성능·안정성을 높인다.

| RAID | 방식 | 특징 |
|---|---|---|
| 0 | 스트라이핑 | 성능 향상, 복구 불가 |
| 1 | 미러링 | 안정성, 용량 절반 |
| 5 | 스트라이핑 + 분산 패리티 | 절충, 디스크 1개 고장 허용 |
| 6 | 이중 패리티 | 디스크 2개 고장 허용 |
| 10 | 미러링 + 스트라이핑 | 성능과 안정성, 비용 높음 |

## 3.2 리눅스 커널 프로그래밍

### 1) 리눅스 개요와 커널 구조

리눅스는 오픈소스 커널로, 다양한 아키텍처와 장치를 지원한다. 사용자 공간과 커널 공간을 분리해 보호한다.

- **사용자 모드**: 응용 프로그램 실행, 제한된 권한
- **커널 모드**: 하드웨어 접근, 모든 메모리 접근
- **시스템 콜**: 모드 전환을 통해 커널 기능 사용

커널은 모놀리식이지만 모듈을 동적으로 적재할 수 있다. `lsmod`, `insmod`, `rmmod`, `modprobe`, `depmod`로 모듈을 관리한다.

### 2) 커널 서비스

**시스템 콜**은 `read`, `write`, `open`, `ioctl`, `mmap`, `fork` 등이 있으며, 내부적으로 커널 함수로 연결된다.

**시그널**은 비동기 이벤트를 프로세스에 전달한다. 커널은 `SIGKILL`, `SIGSTOP` 등 일부를 제외하고 핸들러로 처리할 수 있다.

**/proc**은 커널 상태와 프로세스 정보를 파일 형태로 제공하고, **/sys**는 장치·드라이버 모델을 sysfs로 노출한다. **kobject**는 sysfs의 기본 객체다.

**ioctl**은 장치별 특수 제어 명령을 전달한다. `printk()`는 커널 로그를 남기고 `dmesg`로 확인한다. 로그 레벨은 `KERN_INFO`, `KERN_ERR` 등으로 지정한다.

### 3) 메모리 관리

리눅스는 가상 메모리를 사용하며, 사용자 공간과 커널 공간의 주소 영역이 분리된다.

- **kmalloc**: 연속 물리 메모리, 작은 크기, 빠름
- **vmalloc**: 가상 연속 메모리, 큰 크기, 느림
- **slab/slub**: 자주 쓰는 객체를 캐시해 할당 비용 절감
- **mmap**: 파일이나 장치를 프로세스 주소 공간에 매핑
- **페이지 캐시**: 디스크 I/O 성능 향상

**페이지 폴트**는 접근한 페이지가 물리 메모리에 없을 때 발생한다. **COW(Copy-On-Write)**는 fork 후 쓰기가 발생할 때 페이지를 복사해 메모리를 절약한다.

메모리가 부족하면 **OOM Killer**가 프로세스를 종료해 시스템을 보호한다.

### 4) 디바이스와 파일 시스템

리눅스 디바이스 모델은 버스, 장치, 드라이버를 계층적으로 표현한다. **sysfs**는 `/sys`에, **udev**는 장치 노드를 `/dev`에 생성한다.

**VFS**는 서로 다른 파일 시스템에 공통 인터페이스를 제공한다. 주요 객체는 superblock, inode, dentry, file이다.

- **ext4**: 저널링, 큰 파일·파티션 지원
- **JFS**: IBM의 저널링 파일 시스템
- **LVM**: 논리 볼륨으로 파티션 크기 유연 관리
- **RAID**: mdadm으로 소프트웨어 RAID 구성

마운트는 `mount`, 해제는 `umount`를 사용하며, `/etc/fstab`에 영구 설정한다.

### 5) 네트워크 스택

리눅스 TCP/IP 스택은 응용 계층 → 전송 계층 → 네트워크 계층 → 데이터 링크 계층 순으로 데이터를 처리한다.

**멀티플렉싱**은 여러 응용의 데이터를 하나의 전송 계층으로 모으고, **디멀티플렉싱**은 수신 패킷을 포트·주소로 올바른 응용에 전달한다.

**sk_buff**는 패킷 데이터를 담는 커널 구조체다. **netfilter**는 패킷 필터링·NAT·포워딩 훅을 제공한다. 네트워크 장치 드라이버는 `net_device` 구조체와 `ndo_start_xmit` 콜백으로 패킷을 송신한다.

## 3.3 시스템 및 네트워크 프로그래밍

### 1) 프로세스와 파일 처리

**fork()**는 자식 프로세스를 생성하고, 부모와 자식은 각각 반환값으로 구분한다. 자식은 0, 부모는 자식 PID를 받는다. **exec** 계열은 프로세스 이미지를 교체한다.

**좀비 프로세스**는 종료했지만 부모가 `wait()`로 수거하지 않은 프로세스다. **고아 프로세스**는 부모가 먼저 종료된 프로세스로 init이 입양한다.

**파일 디스크립터(FD)**는 열린 파일을 가리키는 정수다. `open`, `read`, `write`, `close`, `lseek`로 저수준 I/O를 수행하고, `fopen`, `fread`, `fwrite`로 고수준 I/O를 수행한다.

```c
int fd = open("data.bin", O_RDONLY);
if (fd < 0) { perror("open"); return 1; }

char buf[128];
ssize_t n = read(fd, buf, sizeof(buf));
if (n > 0) write(STDOUT_FILENO, buf, n);
close(fd);
```

`dup()`는 파일 디스크립터를 복제하고, `dup2()`는 지정한 번호로 복제한다. 셸의 리다이렉션은 `dup2()`로 구현된다.

### 2) IPC

**IPC(Interprocess Communication)**는 프로세스 간 데이터 교환 기법이다.

| 기법 | 특징 |
|---|---|
| Pipe | 부모-자식 간 단방향, 메모리 기반 |
| FIFO | 이름 있는 파이프, 무관한 프로세스도 사용 |
| Shared Memory | 가장 빠름, 동기화 필요 |
| Message Queue | 메시지 단위, 커널이 관리 |
| Semaphore | 공유 자원 접근 제어 |
| Socket | 네트워크·로컬 통신, 범용 |

**mmap()**은 파일이나 익명 메모리를 주소 공간에 매핑한다. `MAP_SHARED`는 다른 프로세스와 공유하고, `MAP_PRIVATE`는 COW로 복사한다.

공유 메모리는 빠르지만 경쟁 조건이 생기므로 세마포·뮤텍스로 보호해야 한다.

### 3) I/O 멀티플렉싱

**블로킹 I/O**는 완료될 때까지 대기하고, **논블로킹 I/O**는 즉시 반환한다. **동기 I/O**는 완료를 기다리고, **비동기 I/O**는 완료 통지를 받는다.

**select**는 FD 집합을 순회하며 준비된 FD를 찾는다. FD 수 제한(보통 1024)이 있고 매번 복사·순회 비용이 든다. **poll**은 FD 배열을 사용해 제한을 완화한다. **epoll**은 커널이 관심 FD를 관리해 대규모 연결에 효율적이다.

| 방식 | 특징 |
|---|---|
| select | 이식성 좋음, FD 수 제한 |
| poll | FD 수 제한 완화, 배열 순회 |
| epoll | 이벤트 기반, 대규모 연결에 유리 |

epoll은 **레벨 트리거**(준비 상태인 동안 계속 통지)와 **엣지 트리거**(상태 변화 시 한 번 통지)로 동작한다. 엣지 트리거는 데이터를 끝까지 읽어야 한다.

```c
int epfd = epoll_create1(0);
struct epoll_event ev = { .events = EPOLLIN, .data.fd = listen_fd };
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

struct epoll_event events[64];
int n = epoll_wait(epfd, events, 64, -1);
for (int i = 0; i < n; i++) {
    if (events[i].data.fd == listen_fd) accept_client();
    else handle_read(events[i].data.fd);
}
```

### 4) 스레드 프로그래밍

POSIX 스레드는 `pthread` API를 사용한다.

```c
void *worker(void *arg) {
    int id = *(int *)arg;
    printf("thread %d\n", id);
    return NULL;
}

pthread_t tid;
int id = 1;
pthread_create(&tid, NULL, worker, &id);
pthread_join(tid, NULL);
```

**뮤텍스**는 임계구역을 보호하고, **조건 변수**는 특정 조건이 만족될 때까지 대기·통지한다. **배리어**는 모든 스레드가 도착할 때까지 동기화한다.

**스레드 안전**한 함수는 여러 스레드가 동시에 호출해도 문제가 없다. **재진입 가능(Reentrant)** 함수는 정적·전역 상태를 사용하지 않아 인터럽트에서도 안전하다. `strtok()` 대신 `strtok_r()`을 사용하는 이유다.

### 5) 시그널 처리

시그널은 프로세스에 비동기적으로 전달되는 소프트웨어 인터럽트다.

| 시그널 | 의미 | 기본 동작 |
|---|---|---|
| SIGINT | Ctrl+C | 종료 |
| SIGTERM | 정상 종료 요청 | 종료 |
| SIGKILL | 강제 종료 | 종료 (무시 불가) |
| SIGSTOP | 실행 중지 | 중지 (무시 불가) |
| SIGSEGV | 잘못된 메모리 접근 | 코어 덤프 |
| SIGCHLD | 자식 상태 변화 | 무시 |
| SIGALRM | 알람 타이머 | 종료 |

`signal()`보다 `sigaction()`이 이식성과 제어 면에서 권장된다. 핸들러에서는 `printf`처럼 안전하지 않은 함수를 피하고, `volatile sig_atomic_t` 플래그를 사용하는 것이 안전하다.

**SIGCHLD**를 처리해 `waitpid()`로 자식을 수거하면 좀비를 방지할 수 있다. 시그널은 `sigprocmask()`로 블록·언블록할 수 있다.

### 6) 소켓 프로그래밍

**TCP**는 연결 지향, 신뢰성, 순서 보장, 흐름·혼잡 제어를 제공한다. **UDP**는 비연결, 빠름, 순서·신뢰성 미보장이다.

TCP 서버 흐름은 `socket()` → `bind()` → `listen()` → `accept()` → `read/write()` → `close()` 순서다. 클라이언트는 `socket()` → `connect()` → `read/write()` → `close()` 순서다.

```c
int sock = socket(AF_INET, SOCK_STREAM, 0);
struct sockaddr_in addr = {
    .sin_family = AF_INET,
    .sin_port = htons(8080),
    .sin_addr.s_addr = htonl(INADDR_ANY),
};
bind(sock, (struct sockaddr *)&addr, sizeof(addr));
listen(sock, 5);

int client = accept(sock, NULL, NULL);
char buf[256];
read(client, buf, sizeof(buf));
write(client, "OK", 2);
close(client);
close(sock);
```

**바이트 순서**는 호스트와 네트워크가 다를 수 있어 `htons()`, `htonl()`, `ntohs()`, `ntohl()`로 변환한다. **IP 주소 변환**은 `inet_pton()`, `inet_ntop()`을 사용한다.

# 4. 임베디드 소프트웨어

## 4.1 임베디드 프로그래밍

### 1) 자료구조

자료구조는 데이터를 효율적으로 저장·접근하기 위한 구조다. 시간 복잡도는 시험에서 자주 비교된다.

| 구조 | 접근 | 삽입/삭제 | 특징 |
|---|---|---|---|
| 배열 | O(1) | O(n) | 연속 메모리, 캐시 효율 |
| 연결 리스트 | O(n) | O(1) | 포인터, 메모리 단편화 |
| 스택 | O(1) | O(1) | LIFO |
| 큐 | O(1) | O(1) | FIFO |
| 이진 탐색 트리 | 평균 O(log n) | 평균 O(log n) | 편향 시 O(n) |
| 힙 | O(1) 최댓값 | O(log n) | 우선순위 큐 |
| 해시 | 평균 O(1) | 평균 O(1) | 충돌 처리 필요 |

**연결 리스트**는 노드가 포인터로 연결된다. 단일 연결 리스트, 이중 연결 리스트, 원형 연결 리스트가 있다. 삽입·삭제는 빠르지만 임의 접근은 느리다.

**스택**은 함수 호출, 괄호 검사, 후위 표기식 계산에 사용한다. **큐**는 작업 스케줄링, BFS, 버퍼에 사용한다. **원형 큐**는 배열의 끝과 처음을 연결해 공간을 재사용한다.

**트리**는 계층 구조다. 이진 탐색 트리는 왼쪽 < 루트 < 오른쪽을 유지한다. **AVL 트리**는 높이 균형을 맞춰 O(log n)을 보장한다. **힙**은 완전 이진 트리로, 최대 힙은 부모가 자식보다 크다.

**그래프**는 정점과 간선으로 구성된다. 인접 행렬은 밀집 그래프에, 인접 리스트는 희소 그래프에 유리하다. **DFS**는 스택·재귀로 깊이 우선 탐색하고, **BFS**는 큐로 너비 우선 탐색한다.

**정렬**은 버블·선택·삽입(O(n²)), 퀵·병합·힙(O(n log n))이 있다. **탐색**은 순차 탐색과 이진 탐색이 있다. 이진 탐색은 정렬된 배열에서 O(log n)이다.

**해시**는 키를 해시 함수로 변환해 저장 위치를 찾는다. 충돌 해결은 체이닝(연결 리스트)과 개방 주소법(선형·이차·이중 해싱)이 있다.

### 2) C 프로그래밍

C는 임베디드에서 가장 널리 쓰이는 언어로, 하드웨어에 가깝고 이식성이 높다.

- **데이터 타입**: `char`, `int`, `float`, `double`, `short`, `long`, `unsigned`
- **연산자**: 산술, 관계, 논리, 비트, 대입, 삼항
- **제어문**: `if`, `switch`, `for`, `while`, `do-while`
- **함수**: 값 전달, 반환, 재귀
- **포인터**: 주소를 저장하는 변수

**포인터와 배열**은 밀접하다. 배열 이름은 첫 원소의 주소로 decay된다. `a[i]`는 `*(a+i)`와 같다. 포인터 연산은 타입 크기 단위로 이루어진다.

```c
int arr[3] = {10, 20, 30};
int *p = arr;
printf("%d %d\n", *(p + 1), p[2]);  // 20 30
```

**구조체**는 서로 다른 타입을 묶고, **공용체**는 같은 메모리를 여러 타입으로 해석한다. **비트 필드**는 레지스터 표현에 유용하다.

**메모리 영역**은 코드(text), 초기화 데이터(data), 비초기화 데이터(bss), 힙, 스택으로 나뉜다. 힙은 `malloc/free`, 스택은 함수 호출과 지역 변수에 사용된다.

**비트 연산**은 레지스터 제어의 기본이다.

```c
#define BIT(n)        (1u << (n))
#define SET_BIT(r, n) ((r) |=  BIT(n))
#define CLR_BIT(r, n) ((r) &= ~BIT(n))
#define TOG_BIT(r, n) ((r) ^=  BIT(n))
#define GET_BIT(r, n) (((r) >> (n)) & 1u)
```

**`volatile`**은 컴파일러가 접근을 최적화하지 않도록 해 MMIO 레지스터나 인터럽트 공유 변수에 사용한다. **`const`**는 읽기 전용, **`static`**은 파일 범위 또는 정적 수명을 의미한다.

**전처리기**는 `#include`, `#define`, `#ifdef`, `#pragma`로 컴파일 전 텍스트를 처리한다. 헤더 중복 포함은 include guard로 방지한다.

**함수 포인터**는 콜백, 상태 머신, 드라이버 인터페이스에 사용한다.

```c
typedef void (*handler_t)(int);
void on_event(int code) { /* ... */ }
handler_t h = on_event;
h(1);
```

**임베디드 C 팁:** 동적 할당을 피하고 정적 버퍼를 사용한다. 정수 오버플로와 엔디언을 고려한다. `sizeof`는 타입 크기를 바이트로 반환한다. 패딩으로 구조체 크기가 예상보다 커질 수 있어 `offsetof`와 정렬을 확인한다.

### 3) 객체지향 프로그래밍

객체지향은 데이터와 기능을 객체로 묶어 재사용성·유지보수성을 높인다.

- **캡슐화**: 데이터와 메서드를 묶고 내부 구현을 숨김
- **상속**: 기존 클래스의 특성을 물려받음
- **다형성**: 같은 인터페이스로 여러 구현을 호출
- **추상화**: 핵심 특징만 모델링

**오버로딩**은 같은 이름의 메서드를 매개변수로 구분하고, **오버라이딩**은 상속받은 메서드를 재정의한다.

C++에서는 `class`, 생성자/소멸자, 접근 지정자(`public`, `protected`, `private`), 가상 함수(`virtual`)를 사용한다. 가상 함수는 런타임 다형성을 제공하며 vtable로 구현된다. 소멸자는 `virtual`로 선언해 상속 시 올바르게 해제되도록 한다.

```cpp
class Sensor {
public:
    virtual ~Sensor() {}
    virtual int read() = 0;   // 순수 가상 함수
};

class TempSensor : public Sensor {
public:
    int read() override { return 25; }
};
```

Java는 JVM 위에서 동작하며 가비지 컬렉션, 인터페이스, 예외 처리를 제공한다. 임베디드에서는 자원 제약 때문에 C++를 선택적으로 사용하거나 Java ME/Android를 사용한다.

### 4) 안드로이드 응용 개발

안드로이드 애플리케이션은 **Java/Kotlin**으로 작성하며, 화면은 **XML 레이아웃**과 **액티비티(Activity)** 로 구성한다.

- **View**: 화면을 구성하는 기본 요소 (TextView, Button, EditText, ImageView 등)
- **Widget**: 사용자의 입력을 받는 컨트롤 역할의 View
- **Layout**: View를 담아 배치하는 컨테이너 (LinearLayout, RelativeLayout, ConstraintLayout 등)
- **Activity**: 하나의 화면을 담당하며 `setContentView()`로 레이아웃을 연결

`res/layout/activity_main.xml`에 화면을 정의하고, 코드에서 `setContentView(R.layout.activity_main)`으로 표시한다.

```xml
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <TextView
        android:id="@+id/label"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Hello Android" />

    <Button
        android:id="@+id/btn"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="확인" />
</LinearLayout>
```

```kotlin
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        findViewById<Button>(R.id.btn).setOnClickListener {
            findViewById<TextView>(R.id.label).text = "눌렀습니다"
        }
    }
}
```

- **매니페스트(AndroidManifest.xml)**: 액티비티, 권한, 앱 구성을 선언
- **리소스**: `res/values/strings.xml`, `res/drawable/`, `res/layout/`에 문자열·이미지·화면을 분리
- **4대 컴포넌트**: Activity, Service, Broadcast Receiver, Content Provider
- **생명주기**: `onCreate → onStart → onResume → onPause → onStop → onDestroy`
- **NDK/JNI**: C/C++ 네이티브 코드를 JNI로 호출해 하드웨어 제어나 성능이 중요한 부분을 구현

### 5) 멀티미디어 정보처리

**아날로그 → 디지털 변환**은 표본화(Sampling) → 양자화(Quantization) → 부호화(Encoding) 순서다.

- **표본화**: 나이퀴스트 정리에 따라 최대 주파수의 2배 이상으로 샘플링
- **양자화**: 연속 값을 유한 레벨로 근사, 비트 수가 많을수록 정밀
- **부호화**: 디지털 비트열로 표현

**PCM**은 대표적인 비압축 디지털 오디오 방식이다. **압축**은 무손실(FLAC, PNG, ZIP)과 손실(JPEG, MP3, MPEG)로 나뉜다.

- **JPEG**: 정지영상, DCT와 양자화, 손실 압축
- **MPEG**: 동영상, 시간적 중복 제거(움직임 보상)
- **H.264/AVC**: 높은 압축 효율의 동영상 코덱
- **MP3**: 인간 청각의 심리음향 모델을 이용한 손실 오디오 압축

**영상 처리**는 밝기·색상 변환, 필터링, 에지 검출, 이진화 등을 수행한다. 임베디드에서는 연산량과 메모리 대역폭을 고려해 DSP, GPU, 하드웨어 가속기를 사용한다.

## 4.2 개발도구 및 테스팅

### 1) 컴파일러·링커·디버거

C 프로그램 빌드 과정은 다음과 같다.

1. **전처리**: `#include`, `#define` 확장
2. **컴파일**: C → 어셈블리
3. **어셈블**: 어셈블리 → 오브젝트 파일
4. **링크**: 오브젝트·라이브러리 → 실행 파일

**ELF**는 실행 파일, 오브젝트 파일, 공유 라이브러리의 표준 형식이다. `.text`, `.data`, `.bss`, `.rodata`, `.symtab`, `.rel.text` 등의 섹션이 있다.

**정적 링크**는 라이브러리를 실행 파일에 포함해 배포가 단순하지만 크기가 커진다. **동적 링크**는 런타임에 공유 라이브러리를 로드해 메모리를 절약하지만 의존성 관리가 필요하다.

**gcc 옵션**은 다음과 같다.

| 옵션 | 의미 |
|---|---|
| `-c` | 오브젝트 파일까지만 생성 |
| `-o` | 출력 파일 지정 |
| `-g` | 디버그 정보 포함 |
| `-O2` | 최적화 |
| `-Wall` | 경고 표시 |
| `-I` | 헤더 경로 |
| `-L` | 라이브러리 경로 |
| `-l` | 라이브러리 링크 |

**Make**는 파일 변경 시간을 비교해 필요한 부분만 빌드한다. 타깃, 의존성, 명령으로 규칙을 작성한다.

```make
CC = arm-linux-gnueabihf-gcc
CFLAGS = -Wall -O2 -g
TARGET = app
OBJS = main.o sensor.o

$(TARGET): $(OBJS)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(TARGET) $(OBJS)
```

**gdb**는 중단점 설정(`break`), 실행(`run`), 단계 실행(`next`, `step`), 변수 확인(`print`), 스택 확인(`bt`)을 제공한다. 원격 디버깅은 `target remote`로 연결한다.

### 2) 테스팅 기법

테스트 수준은 단위(Unit) → 통합(Integration) → 시스템(System) → 인수(Acceptance)로 구분한다.

- **화이트박스 테스트**: 내부 구조를 알고 경로·조건을 검증
- **블랙박스 테스트**: 입출력만으로 기능 검증

**블랙박스 기법**은 다음과 같다.

| 기법 | 설명 |
|---|---|
| 동등 분할 | 입력을 유효·무효 클래스로 나눔 |
| 경계값 분석 | 경계와 경계 ±1을 테스트 |
| 결정 테이블 | 조건 조합과 동작을 표로 작성 |
| 상태 전이 | 상태와 이벤트 전이를 검증 |
| 유스케이스 | 사용자 시나리오 기반 |

**화이트박스 커버리지**는 문장(Statement), 분기(Branch), 조건(Condition), 조건/분기, MC/DC 등이 있다. 커버리지가 높다고 결함이 없다는 뜻은 아니다.

**테스트 케이스**는 입력, 실행 조건, 기대 결과, 실제 결과로 구성한다. **회귀 테스트**는 수정 후 기존 기능이 깨지지 않았는지 확인한다. **테스트 자동화**는 반복 실행 비용을 줄이고 일관성을 높인다.

## 4.3 소프트웨어공학

### 1) 개발 프로세스

소프트웨어 생명주기(SDLC)는 요구사항 → 분석 → 설계 → 구현 → 테스트 → 유지보수 순서다.

| 모델 | 특징 | 장단점 |
|---|---|---|
| 폭포수 | 순차적, 문서 중심 | 단순하지만 변경 대응 어려움 |
| 프로토타입 | 시제품으로 요구 확인 | 요구 불명확 시 유용 |
| 나선형 | 반복 + 위험 분석 | 대규모·고위험, 비용 큼 |
| 애자일 | 짧은 반복, 고객 협력 | 변화 대응, 문서화 약함 |
| DevOps | 개발·운영 통합 | 배포 자동화, 문화 변화 필요 |

**CMMI**는 프로세스 성숙도를 5단계로 평가한다: Initial(1), Managed(2), Defined(3), Quantitatively Managed(4), Optimizing(5).

### 2) 요구사항 분석과 설계

**요구사항**은 기능 요구사항과 비기능 요구사항(성능, 보안, 사용성, 이식성)으로 나뉜다. 요구사항은 명확하고 검증 가능해야 한다.

**설계 원리**는 모듈화, 추상화, 정보 은닉, 단계적 분해다. 좋은 설계는 **응집도는 높고 결합도는 낮다**.

| 결합도 (낮을수록 좋음) | 응집도 (높을수록 좋음) |
|---|---|
| 자료 < 스탬프 < 제어 < 외부 < 공통 < 내용 | 기능 > 순차 > 통신 > 절차 > 시간 > 논리 > 우연 |

**아키텍처 패턴**은 계층형, 클라이언트-서버, MVC, 파이프-필터, 이벤트 기반, 마이크로서비스 등이 있다.

### 3) UML

UML은 소프트웨어 구조와 동작을 시각적으로 표현하는 표준 언어다.

| 다이어그램 | 용도 |
|---|---|
| 유스케이스 | 사용자와 시스템의 기능 관계 |
| 클래스 | 클래스·속성·메서드·관계 |
| 시퀀스 | 객체 간 메시지 교환 순서 |
| 상태 | 객체의 상태 전이 |
| 활동 | 업무 흐름과 분기 |
| 컴포넌트 | 컴포넌트 구조와 의존성 |
| 배포 | 물리적 배치 |

클래스 관계는 연관, 집합(Aggregation), 합성(Composition), 일반화(상속), 의존, 실체화(Interface 구현)로 구분한다. 집합은 약한 소유, 합성은 강한 소유다.

### 4) 프로젝트 관리

**일정 관리**는 WBS로 작업을 분해하고, 간트 차트로 일정을 시각화한다. **CPM**은 임계 경로를 찾아 최소 완료 기간을 계산하고, **PERT**는 낙관·가능·비관 시간으로 기대 시간을 계산한다.

\[
TE = \frac{O + 4M + P}{6}
\]

**위험 관리**는 위험 식별 → 분석 → 대응 계획 → 추적 순서다. **품질 관리**는 품질 계획, 보증, 통제로 구성된다. **형상 관리**는 버전, 변경, 빌드, 릴리스 관리를 포함한다.

# 5. 실기 필답 대비

## 5.1 임베디드 실무

### 1) 하드웨어 및 회로 분석

실기에서는 조합논리회로와 순서논리회로를 **분석·설계**하는 문제가 출제된다.

- 진리표에서 논리식 유도 후 간소화
- 카르노맵으로 최소항 구현
- 플립플롭 여기표와 상태도 작성
- 카운터의 상태 순서와 모듈러스 계산
- 메모리 회로의 주소 디코딩과 칩 셀렉트

**메모리 회로 분석**은 주소선·데이터선·칩 수를 계산하는 문제로 나온다. 예를 들어 4KB 메모리를 1KB 칩 4개로 구성하면 주소선 12개 중 상위 2개로 칩을 선택하고 하위 10개로 칩 내부를 선택한다.

**타이밍 분석**은 전파 지연, 셋업/홀드 시간, 최대 동작 주파수를 계산한다. 조합논리 지연이 \(T_{pd}\)이고 셋업 시간이 \(T_{su}\)이면 최소 클록 주기는 \(T_{pd}+T_{su}\) 이상이어야 한다.

### 2) 임베디드 시스템 성능 및 구조 분석

**기계어 분석**은 주어진 명령어를 해독해 동작과 결과를 설명하는 문제다. 명령어 형식, 주소지정방식, 플래그 변화를 확인한다.

**성능 지표**는 다음과 같다.

\[
CPI = \frac{\text{총 클록 수}}{\text{명령어 수}}
\]

\[
MIPS = \frac{\text{클록 주파수 (Hz)}}{CPI \times 10^6}
\]

\[
\text{실행 시간} = \frac{\text{명령어 수} \times CPI}{\text{클록 주파수}}
\]

**암달의 법칙**은 일부만 개선할 때 전체 성능 향상의 한계를 보여준다.

\[
S = \frac{1}{(1-p) + p/s}
\]

여기서 \(p\)는 개선 대상 비율, \(s\)는 개선 배율이다.

**성능 최적화**는 캐시 적중률 향상, 메모리 접근 감소, 파이프라인 효율 개선, 불필요한 인터럽트 감소로 이루어진다. **가상 메모리**는 페이지 테이블과 TLB, 페이지 폴트 처리 과정을 설명할 수 있어야 한다.

### 3) 주변장치 분석

데이터시트를 보고 레지스터를 제어하는 프로그램을 작성하는 유형이 중요하다.

- **단순 입출력**: GPIO 방향·데이터 레지스터 설정
- **스캐닝 입출력**: 여러 입력을 순차적으로 읽어 키패드 등 처리
- **인터럽트 입출력**: ISR에서 플래그 확인·데이터 읽기
- **DMA 전송**: 시작 주소·크기 설정 후 완료 대기
- **시리얼 포트**: 보율·데이터 비트·패리티 설정, 송수신
- **타이머**: 프리스케일러·주기 설정, 인터럽트
- **센서**: ADC 값 읽기, 변환 공식 적용

```c
// 폴링 방식 버튼 입력
while (!(GPIOA->IDR & (1u << 0))) { }
while (GPIOA->IDR & (1u << 0)) { }
```

인터럽트 방식은 메인 루프에서 대기하지 않고 ISR에서 이벤트를 처리하므로 응답성이 좋다. 공유 변수에는 `volatile`을 붙인다.

## 5.2 펌웨어·플랫폼 실무

### 1) 펌웨어 설계·구현·테스팅

- **ELF와 binutils**: `readelf -S`, `objdump -d`, `objcopy -O binary`
- **스타트업 코드**: 벡터 테이블, 스택, `.data`/`.bss` 초기화
- **칩 셀렉트 로직**: CS 신호와 주소 영역 설계
- **메모리 초기화**: DRAM 컨트롤러, 타이밍 파라미터
- **부팅 과정**: Boot ROM → 부트로더 → 커널 → init
- **initramfs**: 최소 루트 파일 시스템 구성
- **플래시 제어**: 지우기·쓰기·읽기, 배드 블록, ECC
- **전원관리**: 슬립 모드, DVFS, wake-up source

실기에서는 "부팅이 되지 않는 원인을 설명하라"처럼 단계별 점검을 묻는다. 전원 → 클록 → 리셋 → 부트로더 → DRAM → 커널 이미지 → 루트 파일 시스템 순으로 확인한다.

### 2) 포팅과 디바이스 드라이버

**커널 포팅**은 아키텍처 코드, 보드 파일, Device Tree, 클록·핀·메모리 설정을 타깃에 맞게 수정하는 작업이다.

**부트로더 포팅**은 DRAM 초기화, UART 콘솔, Flash 드라이버, 환경 변수 저장소, 커널 로드 주소를 설정한다.

**디바이스 드라이버 작성**은 다음 순서를 따른다.

1. 데이터시트에서 레지스터 맵과 메모리 맵 확인
2. `file_operations` 또는 서브시스템 콜백 정의
3. `probe()`에서 자원 예약·ioremap·초기화
4. `read/write/ioctl` 구현
5. 인터럽트 등록과 처리
6. Makefile 작성 및 모듈 빌드

```make
obj-m += mydrv.o
KDIR := /lib/modules/$(shell uname -r)/build
PWD  := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
```

**인터럽트 처리**는 상반부에서 빠르게 플래그를 지우고, 하반부에서 무거운 작업을 처리한다. 공유 자원은 스핀락·뮤텍스로 보호한다.

### 3) 커널 프로그래밍

- 커널 디렉터리 구조와 역할
- 시스템 콜 호출 과정
- 프로세스·메모리·파일·장치 관리 시스템 콜
- 세마포·뮤텍스·스핀락
- 소켓 프로그래밍
- 교차 컴파일과 IDE 사용

**커널 오류 디버깅**은 `printk`, `dmesg`, `oops` 메시지, `BUG()`, `WARN()`, ftrace, kgdb를 활용한다. 커널 패닉 시 스택 트레이스와 콜 스택을 확인한다.

## 5.3 소프트웨어·장애 대응

### 1) 프로그램 분석·설계·작성

주어진 요구사항을 UML로 표현하고, 설계 산출물을 코드로 구현하는 문제가 나온다.

- 유스케이스 다이어그램으로 액터와 기능 정의
- 클래스 다이어그램으로 구조 설계
- 시퀀스 다이어그램으로 동작 순서 표현
- 상태 다이어그램으로 이벤트 전이 표현
- C/C++/Java로 구현
- 기술 문서·매뉴얼 작성

**좋은 코드**는 가독성, 일관성, 예외 처리, 자원 해제, 테스트 가능성을 갖춘다. 임베디드에서는 정적 할당, 명확한 오류 처리, 하드웨어 접근 격리가 중요하다.

### 2) 개발도구와 테스트

- 컴파일러·IDE·디버거 사용
- 중단점, watch, 메모리 덤프
- 단위 테스트와 테스트 케이스 작성
- 통합 테스트로 모듈 간 상호작용 검증
- 정적 분석 도구로 잠재 결함 검출

**단위 테스트**는 함수·모듈 단위로 입력과 기대 출력을 검증한다. 하드웨어 의존 코드는 인터페이스 뒤로 분리해 호스트에서 테스트할 수 있게 한다.

### 3) 장애 대응 절차

실기에서 장애 대응은 절차와 보고서 작성이 중요하다.

1. **장애 접수**: 내용을 유형별로 분류하고 등급 지정
2. **원인 분석**: 영향력·발생 가능성·발생 시점으로 우선순위 결정
3. **대응 방안 수립**: 복구 시간·자원·세부 계획 정의
4. **장애 복구**: 원인 제거, 자원 확보, 작업 내역 기록
5. **이력 관리**: 조치 완료 보고서 작성, 개선사항 도출
6. **고객 만족도 조사**: 처리 결과 전달 및 피드백 반영

**장애 등급**은 영향 범위와 긴급도로 결정한다. 예를 들어 서비스 전체 중단은 최상위, 일부 기능 저하는 중간, 문의성은 낮은 등급으로 분류한다. **비상 조치**는 복구 중 예외 상황이 발생했을 때 임시 우회·롤백·백업 복원으로 대응한다.

# 6. 기출 기반 필수 암기

## 6.1 계산 문제

### 1) 논리식·수 표현

- 2의 보수: 비트 반전 후 +1
- \(n\)비트 표현 범위: \(-2^{n-1} \sim 2^{n-1}-1\)
- BCD 보정: 9를 초과하거나 자리올림이 발생하면 +6
- 그레이 코드 변환: \(G = B \oplus (B >> 1)\)
- 해밍 코드 패리티 비트 수: \(2^k \ge n + k + 1\)
- 논리식 간소화: 드모르간, 흡수, 카르노맵

### 2) 메모리·캐시

- 메모리 용량 = \(2^{\text{주소선}} \times \text{데이터선}\)
- 워드 수 = 용량 / 워드 크기
- 캐시 라인 수 = 캐시 크기 / 라인 크기
- 직접 매핑 인덱스 비트 = \(\log_2(\text{라인 수})\)
- AMAT = 적중 시간 + 실패율 × 실패 비용
- 페이지 수 = 논리 주소 공간 / 페이지 크기
- 페이지 테이블 크기 = 페이지 수 × 엔트리 크기

### 3) 성능·스케줄링

- CPI = 총 클록 / 명령어 수
- MIPS = 클록 주파수 / (CPI × \(10^6\))
- 실행 시간 = 명령어 수 × CPI / 클록 주파수
- 암달의 법칙: \(S = 1 / ((1-p) + p/s)\)
- 평균 대기시간 = Σ(시작 - 도착) / 프로세스 수
- 반환시간 = 종료 - 도착
- CPU 이용률 = (총 실행시간 / 전체 시간) × 100
- 디스크 접근 시간 = 탐색 + 회전 지연 + 전송 시간

## 6.2 혼동 개념

### 1) 하드웨어·펌웨어

| 혼동 | 구분 |
|---|---|
| SRAM vs DRAM | SRAM은 플립플롭·빠름·비쌈, DRAM은 커패시터·리프레시 |
| NAND vs NOR | NAND는 대용량·블록, NOR는 랜덤 접근·XIP |
| 레지스터 vs 메모리 | 레지스터는 CPU 내부 초고속 소자 |
| 래치 vs 플립플롭 | 래치는 레벨, 플립플롭은 에지 트리거 |
| Moore vs Mealy | 출력이 상태만 / 상태+입력 |
| JTAG vs ISP | JTAG은 디버그·경계 스캔, ISP는 Flash 기록 |
| EEPROM vs Flash | EEPROM은 바이트 단위, Flash는 블록 단위 소거 |

### 2) OS·플랫폼

| 혼동 | 구분 |
|---|---|
| 프로세스 vs 스레드 | 프로세스는 독립 주소 공간, 스레드는 공유 |
| 세마포 vs 뮤텍스 | 세마포는 카운터, 뮤텍스는 소유권 기반 이진 잠금 |
| 페이징 vs 세그멘테이션 | 고정 크기 vs 논리 크기 |
| 교착상태 vs 기아 | 순환 대기 vs 무한 대기 |
| 선점 vs 비선점 | 실행 중 중단 가능 여부 |
| 경성 vs 연성 실시간 | 마감 위반의 치명성 |
| RAID 1 vs 5 | 미러링 vs 분산 패리티 |

### 3) 네트워크·버스

| 혼동 | 구분 |
|---|---|
| TCP vs UDP | 연결·신뢰성 vs 비연결·속도 |
| I2C vs SPI | 2선·주소·ACK vs 4선·CS·전이중 |
| UART vs USART | 비동기 vs 동기/비동기 겸용 |
| 폴링 vs 인터럽트 | CPU가 확인 vs 장치가 통지 |
| 인터럽트 vs DMA | 이벤트 통지 vs 대량 전송 |
| 빅엔디언 vs 리틀엔디언 | 상위 바이트 우선 vs 하위 바이트 우선 |

# 7. 학습 우선순위

## 7.1 1순위: 계산과 기본 구조

### 1) 계산 문제

논리식 간소화, 2의 보수, 메모리 용량·주소 디코딩, 캐시 AMAT, CPI/MIPS, 스케줄링 평균 대기시간은 매회 변형 출제된다. 공식을 외우고 단위를 맞춰 계산하는 연습이 필요하다.

### 2) 회로·메모리

조합논리회로 설계, 플립플롭 상태 전이, 카운터 모듈러스, SRAM/DRAM/Flash 비교는 필기와 실기 모두에서 중요하다. 진리표 → 논리식 → 회로 순서로 직접 그려 보는 것이 효과적이다.

### 3) C·포인터

포인터와 배열, 구조체 정렬, 비트 연산, `volatile`, 메모리 영역, 함수 포인터는 실기 코드 문제의 기본이다. 짧은 코드를 직접 작성하고 출력을 예측하는 연습을 한다.

## 7.2 2순위: OS·커널·드라이버

### 1) OS·커널

프로세스 상태, 스케줄링, 교착상태 4조건, 페이지 교체, 파일 시스템, 시스템 콜은 필기 비중이 높다. 각 개념을 표로 비교해 혼동을 줄인다.

### 2) 드라이버·부트

부트로더 단계, 스타트업 코드, 디바이스 드라이버 `file_operations`, 인터럽트 상·하반부, 동기화 기법은 실기 서술형에 자주 나온다. "무엇을 어떤 순서로 하는가"를 설명할 수 있어야 한다.

## 7.3 3순위: 소프트웨어공학·주변

### 1) 소프트웨어공학

개발 프로세스, UML, 응집도·결합도, 테스트 기법은 암기 비중이 높다. 용어의 정의와 장단점을 간단히 정리한다.

### 2) 멀티미디어·네트워크

표본화·양자화, 압축 방식, TCP/UDP, 소켓 흐름, I2C/SPI/UART 비교는 선택형과 단답형에 대비해 핵심만 정리한다.
